# 動画制作ワークフロー 運用ルール集

2026年5〜6月、3者体制(戦略レビュー/北原かえで/Claude Code)でショート〜対談ショート制作を通じて確立した「正しい進め方」の集約。CLAUDE.md(/Volumes/編集用/)の詳細版。

## 0. 体制
- 北原かえで: ターミナル実行 / 違和感判断 / 最終決裁
- Claude Code: 実装・コマンド実行
- 戦略レビュー: 方針判断 / 指示作成 / 暴走検知 / 結果判定
実行は実行役が、北原さんの承認を通して行う。

## 1. 承認・安全(最重要: 1ヶ月で119回徹底)
1. 永続許可(don't ask again)は絶対に押さない・推奨しない。毎回「1」で個別承認。
2. 画面の選択肢番号を確認してから指示(番号は毎回変わりうる)。
3. 破壊的・高コスト操作の前は必ず人間承認: render / 全件処理 / 上書き / git push / 削除。
4. 1個ずつ検証→OKなら本番展開。いきなり全件処理しない。
5. コスト累積を常に意識: API課金(GPT)・再実行回数・render時間。

## 2. データで判断(推測を最小化)
1. 推測で動かない。ロジック調整・原因特定は必ず実データ(word時刻/xlsx/JSON/実ファイル)を読んでから。
2. データを見れば即分かることをAIに任せず、先にデータを確認。
3. 原因を確定してから修正。「たぶんこれ」で直さない。1個直す→検証→次。
4. 既存の動く仕組みを優先。既存を読まずに新規実装を提案しない。

## 3. Claude Code(実装役)の監督
実装役が以下をやろうとしたら止める(「3(No)で」):
- 指示と違う方向への逸脱(例: 末尾調整を頼んだのに頭位置を変え始める/指示にない操作を勝手に足す)
- バグのあるコードをそのまま実行(インデント崩れ・スコープ誤り・添字ズレ。実例: durationSecインデントバグを2回阻止)
- 出すと決めてないものを直す無駄作業(例: 非表示テロップのテキスト修正)
- 検証前の全件展開
- 「構造的限界でできない」という主張(多くは誤り。1ヶ月通して限界主張を否定し恒久対処を積み上げた)
- ルール違反の手順
実装役の主観判定(「OKです」「限界です」)を鵜呑みにしない。明確な基準で再判定。

## 4. 判定の基準
- 合否は明確な基準で: PLAYBOOK / telop-display-rules.md / 期待値 / 実データ。
- 誤検知を排除: 複合語境界・動詞活用・固有名詞(The Well-being)を違反と誤認しない。真の違反だけ対処。
- 結論ファースト。抽象論禁止。必ず具体(どのファイルのどの値をどうするか)。

## 5. コミュニケーション(北原さんの特性)
- 北原さんは論理的に判断している。「直感」「感覚的に」で判断を矮小化しない。
- 既に答えた質問を繰り返さない。履歴を読む。
- 「これ」「これだと思う」と短く返したら直前の選択肢から判断(再確認しない)。
- ターミナル出力の "Searched..." "Read 1 file" 等は実行完了の意味。読み返さない。
- 無駄な前置き禁止。冗長な「学び・反省」で本論を埋めない。前進を優先。
- 指示を機械的に文字通り受けず、文脈を読む。

## 6. 再現性・パターン化
- 一度きりの対処でなく汎用ルール化。確定したらPLAYBOOK/dictionary/split-rules等に書面化。
- 自動化を諦めない(「分析できているなら自動化できるはず」)。手動丸投げ禁止。
- テンプレ本体を直したらGitコミット。
