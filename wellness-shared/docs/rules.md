# テロップルール（汎用）

> 対象: 長尺動画のテロップ・制作ルール
> どのテロップ動画プロジェクトでも適用するルール。
> プロジェクト固有設定は `PROJECT_NOTES.md`、ワークフローは `PLAYBOOK.md` 参照。

---

## A. 絶対ルール（違反厳禁）

| # | ルール | Why | 検出方法 |
|---|---|---|---|
| A1 | **25字以内** | 画面に収まらない・読み切れない | `len(text) > 25` |
| A2 | **句読点禁止「、」「。」** | テロップは句読点なしが自然 | `'、' in text or '。' in text` |
| A3 | **startSec < endSec** | dur=0/逆転は画面に表示されない | `startSec >= endSec` |
| A4 | **連続スペース禁止「  」** | 半角×2は不自然な空白 | `'  ' in text` |
| A5 | **先頭/末尾スペース禁止** | 視覚的に左右余白がずれる | `text.startswith(' ') or text.endswith(' ')` |
| A6 | **隣接オーバーラップ禁止** | テキスト重複表示の原因（クロスフェード演出は例外） | endSec[N] > startSec[N+1] |
| A7 | **cps < 20** | 読み速度の上限、超えると追えない | cps >= 20 = エラー |

## B. 警告レベル（検出するが許容、修正必須ではない）

| # | ルール | 閾値 |
|---|---|---|
| B1 | cps < 15 推奨（快適な読み速度） | cps >= 15 = 警告 |
| B2 | duration >= 0.3秒（最低表示時間） | < 0.3s = 警告 |

## C. 連体修飾分断回避 🟡

**原則**: 連体形（〜する/〜の）+ 形式名詞は同一テロップに収める。

| パターン | 悪い分割 | 良い分割 |
|---|---|---|
| C1 | `[N]「〜する」+ [N+1]「ことができる」` | `[N]「〜することが」+ [N+1]「できる」` |
| C2 | `[N]「〜の」+ [N+1]「ものですね」` | `[N]「〜のものですね」+ [N+1]「〜」` |
| C3 | `[N]「〜する」+ [N+1]「ために」` | `[N]「〜するため」+ [N+1]「に」` |

**移動対象語**: こと / もの / ため / 方 / ような / ように

→ これらが後テロップ先頭にある時、前テロップ末尾に統合（25字以内に収まる場合）。

---

## D. 「ですね」処理 🟢

**原則**: 「ですね」をテロップ先頭に置かない、前テロップ末尾に吸収。

| 悪い分割 | 良い分割 |
|---|---|
| `[N]「〜です」+ [N+1]「ですね〜」` | `[N]「〜ですですね」+ [N+1]「〜」` |

例外: `cam-0087[3]+[4]` のように発話側で「ですね」を連続している場合は許容（自然なリフレイン）。

---

## E. 副詞-動詞分断回避 🔵

**原則**: 副詞と動詞を同テロップに収める。

例:
- 悪: `[N]「しっかり」+ [N+1]「分析する」`
- 良: `[N]「しっかり分析する」+ [N+1]「〜」`

対象副詞: しっかり、もう、まあ、あの、ね、など

---

## F. 誤字・表記統一 🔴

| # | パターン | 例 |
|---|---|---|
| F1 | 同音異義語の誤変換 | 予防/予後、一時/一次 |
| F2 | 助詞抜け | 「専門への先生」→「専門医の先生」 |
| F3 | 文字起こしミス | 「この量病気」→「この病気」 |
| F4 | カタカナ→英字/数字統一 | プロジェクトごとに**表記辞書**を作る（PROJECT_NOTES.md参照） |
| F5 | 言い直し残存 | 「ですねですね」連続を削除 |

### F4の表記辞書ルール

プロジェクト開始時に、英字・数字混在の特殊用語を抽出し、表記統一辞書を作る。
抽出コマンドは `PLAYBOOK.md` の Phase 1 参照。

結果を PROJECT_NOTES.md の「特殊用語表記辞書」に記載 → 全テロップで統一。

| パターン | 判定基準 |

## 修正優先順位

```
🔴 緊急（必ず修正） → 誤字・意味崩壊・言い直し残存
🟠 高（必ず修正）   → cps>=20 など視認不可
🟢 中（推奨）       → 「ですね」先頭
🔵 中（推奨）       → 副詞-動詞分断
🟡 中（推奨）       → 連体修飾分断
```

## オプション機能: 画角切替（Multi-angle）

このベース構成では、複数アングル撮影（front/right/left）を**動画内で切り替えられる**設計:

### 仕組み
- prepare.ts: 各 segment に `angle` 情報（"front"/"right"/"left"）を自動付与
- public/ 配下: front.mp4 / right.mp4 / left.mp4 を配置
- VideoMain.tsx: 87行目 `const angles = [...]` で使用画角を列挙
- VideoMain.tsx: 91行目 `seg.angle === angle &&` フィルタで該当 segment のみ表示

### プロジェクトごとの選択

| 選択 | 設定 | ユースケース |
|---|---|---|
| **3画角切替（デフォルト）** | `angles = ["front", "right", "left"]` | 動きのある演出、視点切替で飽きさせない |
| 2画角 | `angles = ["front", "right"]` | 主な正面 + 補助の1アングル |
| **1画角固定** | `angles = ["front"]` + 91行angleフィルタ削除 | シンプル、切替時の違和感を回避 |

### 固定を選んだ場合の注意

- VideoMain.tsx 91行目 `seg.angle === angle &&` を**削除**する
- 削除しないと、front.mp4 でも angle="right" の segment が表示されず黒画面になる
- public/ 配下に不要なアングル動画があっても問題ないが、容量節約のため削除推奨

→ プロジェクトごとの選択は PROJECT_NOTES.md に記載すること。

## ワークフロー違反時の対処

| 違反 | 対処 |
|---|---|
| A1（25字超過） | 分割または短縮 |
| A2（句読点混入） | 削除 |
| A3（startSec>=endSec） | 前テロップに吸収削除 or 境界時刻修正 |
| A4-A5（スペース） | `str.strip()` で自動削除 |
| A6（オーバーラップ） | endSec を次のstartSec - 0.01に調整 |
| A7（cps>=20） | RESPLITで前テロップに文字を移動、または分割数を増やす |

## H. xlsx 取り扱いルール（事故防止）

### xlsx は北原さんの作業領域
- script_check.xlsx は北原さんの目視チェック・修正記入用
- 戦略Claude / Claude Code は基本「読み取り専用」扱い
- 勝手に再生成しない

### make_excel.py 実行ルール
- 初回の xlsx 生成: OK
- 北原さんの修正案を script.json に反映した後の再生成: OK（北原さん許可必須）
- dictionary 追加で script.json が変わった時: **xlsx は再生成しない**
- 戦略Claude の独自判断のみで実行: **禁止**

### J列入力警告の対応
- make_excel.py 実行時「J列入力 X件あり」が出たら**停止**
- 北原さんに確認してから続行
- バックアップは自動だが、念のため確認

### dictionary 追加と xlsx の関係
- dictionary に追加しても既存 xlsx は再生成不要
- apply_xlsx_proposals_textmatch.py でテキストマッチ反映可能

### dictionary 追加時の正しいフロー

正しい手順:
1. dictionary.json に追記
2. `apply_dictionary_to_script.py --script <path> --dry-run` で差分確認
3. `apply_dictionary_to_script.py --script <path>` で既存 script.json に追加適用
4. xlsx 再生成は北原さん許可後のみ

禁止パターン:
- dictionary 追加 → prepare.ts 再実行 → make_excel.py 実行
- これは北原さんの手動修正を消失させる（罠8-1）

### prepare.ts 実行条件
- master.json が変わった時のみ
- 北原さんの明示的指示がある時のみ
- 実行前に必ず xlsx 修正案を保護（バックアップ + 反映）

### prepare.ts 安全装置（自動）
- script.json に `_meta.lastManualEditAt` がある場合、prepare.ts は自動停止
- 「手動修正済みのため再生成すると失われます」と警告
- 選択肢 A) apply_dictionary_to_script.py または B) --force-overwrite を案内
- 北原さんが特殊フラグを覚える必要なし
