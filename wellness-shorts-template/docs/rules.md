# ショート動画ルール（汎用）

> どの縦型ショート動画プロジェクトでも適用するルール。
> プロジェクト固有設定は `PROJECT_NOTES.md`、ワークフローは `PLAYBOOK.md` 参照。
> このshorts/ツールは複数プロジェクト共通の共用ツール（パターンC）。
> 長尺側の汎用docsは `/Volumes/編集用/wellness-shared/docs/` 参照。

---

## 0. ショート動画の基本仕様

| 項目 | 値 |
|---|---|
| 動画長 | 45〜180秒（1〜3分） |
| 本数 | 30分尺で3〜5本（調整可、configで指定） |
| 解像度 | 1080×1920（縦型） |
| FPS | 30 |
| 元素材解像度 | 1920×1080（横型）→ 縦クロップで縦化 |
| 文字数上限 | 12字（1行表示） |
| フォントサイズ | 通常80px / 強調120px（1.5倍） |
| 強調方式 | サイズUPのみ（色は将来変更可、当面白固定） |
| テロップ位置 | 下部1/3（YouTubeショート風） |
| テロップ背景 | 黒縁+白文字 |
| BGM | なし |

---

## A. 絶対ルール（違反厳禁）

| # | ルール | Why | 検出方法 |
|---|---|---|---|
| A1 | **12字以内（1行）** | 縦型では1行が読みやすさの絶対条件 | `len(text) > 12` |
| A2 | **句読点禁止「、」「。」** | テロップは句読点なしが自然 | `'、' in text or '。' in text` |
| A3 | **startSec < endSec** | dur=0/逆転は画面に表示されない | `startSec >= endSec` |
| A4 | **連続スペース禁止** | 半角×2は不自然な空白 | `'  ' in text` |
| A5 | **先頭/末尾スペース禁止** | 視覚的に左右余白がずれる | `text.startswith(' ') or text.endswith(' ')` |
| A6 | **隣接オーバーラップ禁止** | テキスト重複表示の原因 | endSec[N] > startSec[N+1] |
| A7 | **cps < 20** | 読み速度の上限 | cps >= 20 = エラー |
| A8 | **音声タイミング同期** | master.json word-level に厳密準拠 | wordベースで startSec/endSec を生成 |

---

## B. 警告レベル（検出するが許容）

| # | ルール | 閾値 |
|---|---|---|
| B1 | cps < 15 推奨 | cps >= 15 = 警告 |
| B2 | duration >= 0.3秒 | < 0.3s = 警告 |
| B3 | ショート尺の上下限 | < 45s または > 180s = 警告 |

## C-Hook. 冒頭3秒ルール 🔴（離脱対策）

**原則**: ショートの最初3秒は視聴者の離脱判定の関門。離脱されたら全て無意味。
YouTube/TikTokショートでは冒頭3秒で約半数が離脱するため、ここに最大の設計リソースを投入する。

### C-Hook1. 最初のテロップは「結論先出し型」

- 「実はAIで全部変わる」「これで人生変わる」など断定的・結論的な掴み
- 「自己紹介します」「今日のテーマは」など導入型はNG
- 該当区間が長尺中に見つからない場合は、GPTに「冒頭3秒に置ける結論文」を生成させる
- 検出: candidates.json の最初のテロップが導入型なら警告

### C-Hook2. 冒頭3秒内に強調語(120px)を1個以上配置

- GPT強調語判定で最低1個を3秒以内に配置
- 強調語なしの「平坦な冒頭」を禁止
- 検出: telops[0..N].endSec <= 3.0 の範囲に emphasis フィールドを持つテロップが0個ならエラー

### C-Hook3. 冒頭3秒内にカメラ切替を1回以上

- solo モードでも冒頭は3秒以内で1回切替を強制
- 例: 0秒front → 1.5秒right → 切替後そのまま続行
- 動きで視覚的に「何か始まる」感を出す
- 検出: cameraSwitches[0..N].atSec <= 3.0 が2個未満ならエラー（開始位置 + 切替1回 = 計2個必要）

### C-Hook4. 冒頭テロップは視覚アニメーション必須

- 冒頭テロップは静的表示禁止、何らかの視覚アニメーションを伴う
- 具体形（フェード、スライド、スケール、遅延ポップ等）は `configs/<project>.json` の `animations` で指定
- 方向や種類は問わないが、「動きで視聴者の目を引く」ことが目的
- 検出: animations.firstTelop が configs に未定義ならエラー

## C. 強調語ルール 🟡

**原則**: 1つのショートで強調語は **3〜7個**。多すぎると強調にならない。

### 強調対象（GPTで判定）

| カテゴリ | 例 |
|---|---|
| 数値 | 「10年」「3割」「2026年」 |
| 固有名詞 | 「AI」「Netflix」「PHR」 |
| 感嘆・転換 | 「実は」「絶対」「本当に」 |
| キーワード | そのトピックの核となる単語 |

### 強調しない

- 助詞・助動詞（「を」「が」「です」）
- ありふれた動詞（「思う」「考える」「言う」）
- 12字制約を超える強調（強調1語を入れると12字超えるなら諦める）

### 実装

- analyze.ts が GPT(gpt-4o-mini) に「このテロップで強調すべき語を返せ」と問う
- 戻り値を script.json の `emphasis: [start, end]` フィールドに格納
- Telop.tsx が該当文字範囲だけ120pxで描画

## D. カメラ切替ルール 🔵

### モード判定

| モード | 判定 | 切替ルール |
|---|---|---|
| **solo** | 一人語りトピック | 発話の文末（無音0.3秒以上の区切り）で切替、最低3秒・最大10秒 |
| **dialogue** | 対談・複数話者 | 話者ターン（master.jsonにspeaker情報がある場合）で切替 |

### モード指定方法

- ユーザー指示「一人語りの切り抜き作って」→ solo
- ユーザー指示「対談の切り抜き作って」→ dialogue
- configs/<project>.json の `mode` で固定指定も可

### solo切替アルゴリズム

```
1. master.json から無音0.3秒以上の区切りを抽出
2. 区切りを「切替候補点」とする
3. 切替候補点から、前回切替から3秒以上経過した最初の点を選ぶ
4. ただし最大10秒で強制切替
5. 切替先カメラは front/left/right からランダム（直前と同じは除外）
```

### dialogue切替アルゴリズム

```
1. master.json の speaker フィールドを読む
2. speaker が変化した瞬間に切替
3. 単一話者でも12秒以上同じカメラなら strategic に front/left/right ローテーション
```

## E. 縦型クロップルール 🟢

### 方式

**カメラ別固定オフセット**（configs/<project>.json で指定）。

```json
"cropOffsets": {
  "front": { "x": 420, "y": 0 },
  "left":  { "x": 320, "y": 0 },
  "right": { "x": 520, "y": 0 }
}
```

- 元素材1920×1080 → 1080×1920に縦クロップ
- 横方向オフセット: 0〜840（1920-1080=840が右端）
- 縦方向: 基本0（横素材を縦に伸ばすため上下黒帯は出さない・別途設計）

### 縦化方針

- 横1920を中央寄り or 被写体側にオフセットして1080幅で切り取り
- 縦1080 → 1920に拡大表示（被写体が画面いっぱい）
- 上下にテロップ用余白を確保（テロップは下部1/3）

## F. 盛り上がり検出ルール 🟠

### 検出フロー

```
1. topics.json を読む（14トピックなど、長尺で生成済み）
2. 各トピックに対して gpt-4o-mini で評価
   入力: トピックのlabel + startSec/endSec + 該当区間のmaster.json word列
   出力: ショート向きスコア（0-10）+ 切り出し推奨区間（startSec/endSec）+ タイトル案
3. スコア上位N件を採用（configで本数指定、デフォルト3〜5本）
4. 各採用トピックを 45〜180秒に収まるよう調整
```

### スコア判定基準（GPTへのプロンプト方針）

- 数値・固有名詞・断定が多い → 高スコア
- 質問→回答の完結性 → 高スコア
- 笑い・感嘆など感情の動き → 高スコア
- 専門用語の連発で一般視聴者が置いていかれる → 低スコア
- 言い淀み・トピック転換途中 → 低スコア

## G. 文法ルール（長尺と共通）

長尺の `/Volumes/編集用/wellness-shared/docs/rules.md` の C〜F群（連体修飾分断・ですね・副詞・誤字）と同じ。
**ショートでは12字制限のため、より厳格な短縮判断が必要**。

### ショート固有の短縮指針

| パターン | 対応 |
|---|---|
| 「〜だと思います」「〜なんですよね」 | 削除して核だけ残す |
| 「えーと」「あの」「まあ」 | 削除 |
| 「〜ということで」 | 「〜で」に短縮 |
| 主語省略可能なら省略 | 文脈で分かる主語は削る |

## J. 修正優先順位

```
🔴 緊急（必ず修正） → 誤字・意味崩壊・12字超過・C-Hook違反
🟠 高（必ず修正）   → cps>=20、A群全般
🟢 中（推奨）       → 強調語の選定見直し
🔵 中（推奨）       → カメラ切替タイミング違和感
🟡 中（推奨）       → 縦型クロップの被写体見切れ
```

## L. ワークフロー違反時の対処

| 違反 | 対処 |
|---|---|
| A1（12字超過） | RESPLITで分割、または短縮（D・G参照） |
| A2（句読点混入） | 削除 |
| A3（startSec>=endSec） | 前テロップに吸収削除 or 境界修正 |
| A6（オーバーラップ） | endSec を次のstartSec - 0.01に調整 |
| A7（cps>=20） | 前テロップに文字を移動、または分割数を増やす |
| A8（音声タイミングずれ） | master.json再参照、word単位で再生成 |
| **C-Hook1（導入型冒頭）** | **GPTに「結論先出しの冒頭文」を再生成させる、または別候補に差し替え** |
| **C-Hook2（冒頭強調語ゼロ）** | **GPTに「冒頭3秒に強調語を最低1個」を指示して再抽出** |
| **C-Hook3（冒頭カメラ切替なし）** | **ingest.tsで冒頭3秒以内に強制1回切替を挿入** |
| **C-Hook4（アニメ未定義）** | **configs/<project>.json に animations.firstTelop を追記** |
| 強調が多すぎる | GPTに「3〜7個に絞れ」と再問い合わせ |
| カメラ切替が早すぎる | min interval を 3秒→5秒に上げる |
